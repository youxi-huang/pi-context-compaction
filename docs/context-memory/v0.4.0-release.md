# v0.4.0 — Independent extension preview

v0.4.0 packages the implementation merged in PRs
[#40](https://github.com/youxi-huang/pi-context-compaction/pull/40) and
[#41](https://github.com/youxi-huang/pi-context-compaction/pull/41) for unmodified
official Pi 1.1.0. It remains a GitHub pre-release with a bounded support matrix.
The earlier `v0.4.0-preview.1` candidate was never published and is superseded;
its performance exception does not apply to this release.

## Delivered behavior

- Manual `/compact` and Pi's threshold compaction after a completed text turn
  use the same source, staging and disk-confirmation checks. A blocked session
  or context-overflow failure still needs an explicit retry.
- Arm A prepares once per checkpoint interval with the configured writer. A
  valid candidate can commit its covered prefix without another writer call;
  later originals remain verbatim. Otherwise the configured writer compacts
  synchronously.
- Arm B merges data-only session-model work notes. Covered user messages are
  carried in full, in order. If they do not fit within their bound, or the
  resulting context does not fit below half the threshold, the writer compacts
  with the notes as hints and reads all carried user messages.
- Both arms are off by default. Every writer call is recorded in one
  content-free journal, including cancelled or discarded preparation and calls
  with unknown usage. Preparation failure does not block ordinary work; a failed
  compaction retains the existing durable block and explicit recovery contract.
- Full source and disk checks run at trust boundaries. Requests between them
  check new entries and the session file's identity and length. Same-length
  rewrites are detected at the next boundary and cannot pass checkpoint commit.

The [extension guide](extension-preview.md) describes configuration, supported
sessions, installation and recovery.

## Evidence and limits

The release requires `node scripts/context-memory-ops.mjs ci` to exit 0 on
clean committed source. It includes the focused script/runtime checks, synthetic
host security checks, isolated official-Pi package acceptance, full strict
default-settings scenarios and frozen offline evaluation. The scenario suite
includes both opt-in paths and requires the 50 ms request-overhead target and
checkpoint-growth bound, without performance exceptions or known gaps.

The [validation record](validation.md) keeps the individual synthetic A/B and
Haiku bridge runs, including B's earlier mid-log fact loss and the fix in #41.
In the scripted follow-up, pasted user logs cause B to fall back to the writer;
model-produced logs allow notes commits. Both log modes recover all eight probes
in each arm. B can spend more tokens and still require the writer. These finite
controls establish execution and recovery mechanics, not a general performance
advantage.

The maintainer selects v0.4.0 as the experimental delivery of these paths.
Real-provider whole-task latency, semantic recovery, complete billing and cache
behavior remain unmeasured. The original provider A/B acceptance goal stays open;
the release does not claim that either arm is better for ordinary work. The
instruction-authority prototypes were removed, not delivered as a new protocol.
Other Pi versions, attachments, unfinished tool rounds, concurrent writers and
Windows remain outside the verified support matrix.

## Immutable distribution

Install the five-file extension package and restart Pi:

```sh
pi install git:github.com/youxi-huang/pi-context-compaction@extension-v0.4.0
```

`v0.4.0` identifies the development source, not an installable Pi package.
`extension-v0.4.0` identifies the package; `extension-preview` follows later
compatible releases. Pi itself and its credentials are not replaced.

After final-main verification and all three CodeQL checks pass, the existing
publication workflow rebuilds the immutable source tag, repeats official-Pi
acceptance and full strict scenarios, and publishes these assets:

| Asset | Contents |
| --- | --- |
| `pi-context-compaction-preview-0.4.0.tgz` | Independent extension package |
| `pi-context-compaction-v0.4.0-source.tar.gz` | Source at the immutable source tag |
| `release-provenance.json` | Source/tooling commits, package hashes and check URLs |
| `preview-acceptance-profile.json` | Exact-package strict scenario results and timing samples, without session content |
| `SHA256SUMS` | SHA256 checksums for the four assets above |

Publication refuses dirty or mismatched source, failed final-main checks,
incomplete scenario evidence and replacement of existing tags or public assets.
The resident release version and its frozen comparison remain separate.
